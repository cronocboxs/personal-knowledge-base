# personal-knowledge-base アーキテクチャ・設計思想仕様 (Phase 3)

本ドキュメントでは、`personal-knowledge-base` リポジトリにおける「AIエージェントと人間の協調運用」を前提とした構造化ナレッジベースの設計思想、情報ライフサイクル、および自動化アーキテクチャを解説します。

---

## 1. コア設計思想：規約駆動開発 (Rule-Driven Development)

本リポジトリは、AIエージェント（Goose, Claude, Cursor等）が誤操作や機密漏洩を起こさず、自律的かつ高精度にナレッジの蓄積・コード解析を行えるよう、厳格な階層ルール (`00-rules/`) を基盤としています。

### 階層化ディレクトリと編集権限ポリシー
- **`00-rules/` (システム規約)**: 参照専用。情報ライフサイクル、ファイル分類、プライバシー保護の絶対ルール。
- **`01-private/` (最高機密)**: `.gitignore` 対象。個人情報や認証情報は一切外部へ出力しない。
- **`02-knowledge/` (構造化ナレッジ)**: エージェントがリポジトリ解析や調査結果をもとに段階的（Phase 1〜3）に深掘り・反復進化させる事実・概念メモ。
- **`03-output/` (成果物)**: ナレッジから生成された記事、レポート、ドラフトコード。
- **`04-resources/` (一次情報原本)**: Web素材やリポジトリ原本。**絶対に書き換え・直接修正しない（非破壊の原則）**。
- **`05-todo/` (タスク管理)**: エージェントおよび人間の進捗ロードマップ。
- **`06-storage/` (バイナリ・大容量データ)**: `.gitignore` 対象。
- **`99-trash/` (退避スペース)**: 物理削除 (`rm`) の代わりに移動させる安全領域。
- **`scripts/` (自動化スクリプト)**: メンテナンス・Git連携・検証スクリプト。
- **`.agents/skills/` (スキル定義)**: エージェントの拡張スキル手順書 (`ingest-repo-knowledge` 等)。

---

## 2. 知識進化（Knowledge Evolution）アルゴリズム

`02-knowledge/` 配下のナレッジは、エージェントスキル（例: `ingest-repo-knowledge`）によって以下のステップで反復進化します：
1. **Phase 1 (概要作成)**: ディレクトリ構造、全体像、依存関係の書き出し。
2. **Phase 2 (コード深掘り)**: Controller / Service / Model 等の具体的な処理・データフローの解読。
3. **Phase 3 (設計思想の抽出)**: なぜその設計か、責務分離・アーキテクチャパターンの体系化。
4. **メンテナンス**: 差分更新と自動 `git commit`。

---

## 3. 自動化と安全性担保の仕組み
- **非破壊性とファイル移動制約**: `rm` コマンドの使用禁止と `99-trash/` への退避徹底。
- **Git 連携自動化**: ナレッジ更新やリポジトリ解析完了時に自動でステージングおよびコミットを実施し、トレーサビリティを確保。
