# ルールとワークフロー仕様

本ドキュメントでは、`personal-knowledge-base` における各種システム規約および情報ライフサイクル・フローについて解説します。

## 1. 絶対遵守ルール（Core Mandatory Rules）

1. **最高機密の保護**: `01-private/` 内の情報（個人情報・認証情報等）を外部へ出力・送信・要約露出し落としてはならない (`.gitignore` 対象)。
2. **原本の非破壊**: `04-resources/` 内の一次情報原本は絶対に書き換え・修正・直接削除しないこと。
3. **ファイル移動の徹底**: ファイルの直接物理削除（`rm`）は禁止。不要ファイルは必ず `99-trash/` へ移動すること。
4. **事前承認の義務**: ディレクトリ構造の変更、大量ファイルの移動・一括書き換え時は、事前にユーザーの承認を得ること。

## 2. 情報ライフサイクル・フロー (`00-rules/workflow.md`)

情報をリポジトリ内で扱う際の標準的なステップは以下の通りです：

1. **収集 (`04-resources/`)**: Web記事、リポジトリ、PDF等の一次情報をそのまま保管する（書き換え厳禁）。
2. **知識化 (`02-knowledge/`)**: 一次情報を読み解き、エージェントや人間が再利用しやすい構造化された Markdown ノートへ書き起こす。
3. **成果物化 (`03-output/`)**: 蓄積された知見をベースに、記事、レポート、コードなどの成果物を生成する。
4. **タスク管理 (`05-todo/`)**: 進捗やロードマップを管理し、継続的な改善を行う。

## 3. ファイル命名・記述規約 (`00-rules/formatting.md`)

- **命名規則**: 原則 `kebab-case.md` または日付プレフィックス `YYYY-MM-DD-title.md` を使用すること。
- **YAML Frontmatter**: 新規Markdownファイルの先頭には必ずメタデータ（`created`, `tags`, `status`）を付与すること。
