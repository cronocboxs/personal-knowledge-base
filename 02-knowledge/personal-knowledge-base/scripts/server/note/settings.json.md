# settings-json 解析ノート

## 1. 概要・目的
このファイルは、アプリケーションが外部のLLM（大規模言語モデル）プロバイダーに接続するための設定（設定ファイル）を定義しています。具体的なモデル名、接続エンドポイント、およびデフォルトの利用プロバイダーを集中管理する役割を担っています。この設定により、コードの変更なしにバックエンドで利用するLLM環境（例：ローカルのOllamaからクラウドのGeminiへ）を切り替えることが可能になっています。

## 2. 主要コンポーネント・関数（設定キー）

本ファイルには「関数」ではなく、利用可能なLLMプロバイダーごとの「設定ブロック（オブジェクト）」が定義されています。

### `default_provider`
* **役割**: アプリケーションが特別な指定をしない場合に、最初に試行または利用するLLMプロバイダーを決定します。
* **値**: `"Ollama (Local LLM)"` が設定されており、デフォルトではローカル環境で動くLLM利用が優先されることを示唆しています。

### `gemini`
* **役割**: Google Gemini APIを利用するための設定ブロックです。
* **`default_model`**: アプリが標準で利用するGeminiのモデル名（`gemini-3.5-flash-lite`）を定義しています。
* **`available_models`**: クライアントに公開されている、あるいは利用可能なモデル名のリストです。

### `ollama`
* **役割**: Ollama（ローカルで動くLLM実行環境）を利用するための設定ブロックです。
* **`default_model`**: デフォルトで利用するOllama上のモデル名（`gemma4:e4b-it-q4_K_M`）を定義しています。
* **`endpoint`**: Ollamaサービスが実際に稼働しているネットワークアドレスとポート（`http://localhost:11434`）を定義しています。これは、アプリケーションがどこに接続すべきかを指定する最も重要な情報の一つです。

## 3. 処理フローと実装ポイント

1. **プロバイダー選択のフロー**:
   アプリケーションがLLM連携を行う際、まず`default_provider`の設定を参照します。これにより、どのAPI接続処理（Gemini APIコールか、Ollama APIコールか）を実行すべきかを決定します。

2. **ローカル環境の優先**:
   `default_provider`がローカルな`Ollama`を示していることから、本アプリケーションは**可能な限りローカルリソースを活用し、外部APIへの依存を最小限に抑える設計思想**を持っていることが読み取れます。

3. **設定の一元管理**:
   全てのLLM接続に関するメタデータ（モデル名、エンドポイント、優先度）がこの一つのファイルに集約されているため、どのプロバイダーのバージョンアップや設定変更も、このファイルを修正するだけで済み、疎結合性が保たれています。

4. **構造の利点**:
   LLMプロバイダーごとにオブジェクトを分離しているため、将来的に新しいプロバイダー（例：Azure OpenAIなど）を追加する場合でも、他の設定部分に影響を与えることなく、新しいキー（例：`azure`）を追加するだけで対応可能です。
