# start-webui-py 解析ノート

## 1. 概要・目的

`start-webui-py.py` は、個人ナレッジベース（Personal Knowledge Base）を視覚的にブラウズ、操作するためのStreamlitベースのWebユーザーインターフェース（WebUI）を提供するPythonスクリプトです。

このスクリプトの主要な目的は、単なるデータストレージではなく、「ナレッジを能動的に扱うためのインターフェース」を提供することにあります。具体的には、以下の機能を担っています。

1.  **ナレッジの可視化**: フォルダ構造（エクスプローラーツリー）をサイドバーに表示し、関連する知識ドメインへのナビゲーションを可能にする。
2.  **AIモデルの統一管理**: ユーザーがローカルLLM（Ollama）とクラウドLLM（Gemini）をシームレスに切り替えて使用できる設定パネルを提供する。
3.  **高度な連携**: 知識の参照（RAG: Retrieval-Augmented Generation）やコンテンツの編集/表示のためのフォーム機能の基盤を提供する。

## 2. 主要コンポーネント・関数

### A. `get_knowledge_categories()`
**役割**: ナレッジベースディレクトリ（`KNOWLEDGE_DIR`）の内容を走査し、上位の知識ドメイン（ディレクトリ）リストを取得します。
**ポイント**: `head/` や `note/` のような内部管理ディレクトリは除外され、ユーザーが分類された主要なトピックのみが抽出されます。

### B. `get_ollama_models()`
**役割**: ローカルで動作しているOllamaサービスに接続し、利用可能なモデルのリストを取得します。
**実装ポイント**: `subprocess.run(["ollama", "list"], ...)` を使用して、システムコマンドを実行し、モデル名（例: `llama2`, `gemma:2b`）を動的に取得します。これにより、利用可能なローカルLLMがUIに反映されます。

### C. `render_explorer_tree(dir_path, ...)`
**役割**: サイドバーに、ナレッジベースのファイルシステムをエクスプローラー形式で描画します。
**ポイント**: Streamlitの `expander` コンポーネントを再帰的に利用してディレクトリ構造を表現しています。ディレクトリ（`dirs`）とファイル（`.md`）を判別し、ファイルをクリックすると、そのファイルの内容をメインフォームエリアにロードするトリガーを発生させます。

## 3. 処理フローと実装ポイント

### A. 初期化と設定（Session State）
スクリプトの初期段階で、Streamlitの `st.session_state` を利用して、UIの状態（例: `edit_mode`, `form_title`, `form_category`）を保存・管理しています。これにより、ユーザーがページを移動しても、フォームの状態や選択したモデル設定が保持されます。

### B. LLMプロバイダーの選択と連携
*   **優先度**: サイドバー最上部で、OllamaとGeminiのいずれを使用するかを選択させます。
*   **Gemini (Cloud)**: APIキーの読み込み（`get_gemini_api_key()`）を必須とし、設定情報を管理します。
*   **Ollama (Local)**: `ollama list` によるモデルリストの動的取得と、接続エンドポイント（`ollama_url`）の設定が可能です。

### C. 知識ベースの表示サイクル
1.  **構造表示**: `render_explorer_tree` が、ファイルシステムの階層構造をサイドバーに常に提供します。
2.  **ファイル選択**: ユーザーがサイドバーのファイルをクリックします。
3.  **コンテンツロード**: `load_file_to_form` が呼び出され、クリックされたファイルのMarkdown内容がメインフォームに表示されます。この機構により、ユーザーはナレッジベース全体を俯瞰しつつ、ピンポイントで内容を閲覧できます。

### 📚 まとめ（重要性）
このスクリプトは、ナレッジベース全体を単なるファイル群として扱うのではなく、**「探査可能なインターフェース」** として定義し直す役割を持っています。これにより、人間が直感的に知識構造を把握し、利用する体験を提供することが目標です。
