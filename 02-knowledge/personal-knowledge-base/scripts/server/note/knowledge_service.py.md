# knowledge_service-py 解析ノート

## 1. 概要・目的

本モジュールは、パーソナルナレッジベース（PKB）における**情報構造化、メタデータ抽出、ナレッジファイル生成**を自動化するためのコアなユーティリティ層を提供します。

単なるコード解析に留まらず、ナレッジベースの「記憶」と「ルール」そのものを組み込むことを目的としています。具体的には、参照している全ての運用規約（`AGENTS.md`, `formatting.md`, `workflow.md`など）や、既存のナレッジベースの概要（SQLite DB経由）をコンテキストとしてLLMに渡し、入力された素材から必要なメタデータ（タグ、親子関係、概要など）を厳密に構造化させる役割を担います。

## 2. 主要コンポーネント・関数

本ファイルは、複数の責務を担うクラス群（実際には関数群）として機能しており、ナレッジワークフローの各種ステップをサポートしています。

| 関数名 | 責務 | 機能の概要 |
| :--- | :--- | :--- |
| `resolve_prompt_path` | **パス解決** | プロンプトやスキル定義（`SKILL.md`など）の指定された入力パスを、システム内のルールや適切な物理パスに柔軟に解決します。検索順序が定義されており、ルール遵守を助けます。 |
| `get_available_prompts` | **プロンプト管理** | 実行可能なプロンプトファイルの一覧を走査ディレクトリから取得し、エージェントに利用可能なプロンプトのコンテキストを提供します。 |
| `load_rule_docs` | **規約集約** | ナレッジベースの動作根幹となる複数のルールファイル（`AGENTS.md`、`formatting.md`、`workflow.md`など）をすべて読み込み、単一のコンテキスト文字列として結合します。これはLLMに対する「システム全体の説明書」として機能します。 |
| `get_existing_notes_context`| **DB参照・コンテキスト化** | SQLiteデータベース（`knowledge_index`）をクエリし、現在存在するナレッジノートのタイトル、パス、概要を読み出します。これにより、LLMは「このナレッジベースには既にどのような情報があるか」を理解した上で、新しいノートを作成できます。 |
| `clean_and_parse_json` | **データ補正** | LLMが生成するJSON出力について、エスケープ文字のミスや特殊文字によるパースエラーを多段階で補正・処理する堅牢なパース関数です。 |
| `generate_knowledge_files` | **ワークフロー実行** | **このモジュールの主機能。** 全体のプロセスを統括し、以下のステップを実行します。1. **規約/DBコンテキストの収集** $\rightarrow$ 2. **LLMへのリクエスト（メタデータ抽出）** $\rightarrow$ 3. **生成されたメタデータに基づいたファイル構造の決定** $\rightarrow$ 4. **最終的なナレッジファイル出力**。 |

## 3. 処理フローと実装ポイント

### 🔄 主要な処理フロー（`generate_knowledge_files`）

1.  **コンテキストの準備**:
    *   `load_rule_docs()`を通じて、すべての運用ルール（`AGENTS.md`など）をロードし、LLMのプロンプトに組み込みます。
    *   `get_existing_notes_context()`を通じて、既に蓄積されたナレッジのサマリをロードし、LLMが重複や関係性を考慮するための背景情報として提供します。
2.  **メタデータ抽出（PASS 1）**:
    *   LLMに対して、提供されたルールブックと既存ナレッジを参照し、入力素材から「タグ」「親子関係」「概要」「ステータス」などの構造化されたYAML属性（`formatting.md`準拠）を抽出するよう指示します。
3.  **ファイル生成（PASS 2）**:
    *   抽出されたメタデータを基に、最終的なナレッジノートの構造を決定し、最終的なアウトプットデータ（JSON形式のテンプレート）を生成します。

### ✨ 重要実装ポイント

*   **ルールの外部化と集約**: 規約が複数のファイルに分かれているため、`load_rule_docs`を通じてそれらを自動的に統合する設計がなされており、エージェントが「何を遵守すべきか」という判断基準を一元的にLLMに提示できています。
*   **DB駆動型のコンテキスト**: 既存のナレッジをSQLiteから読み出すことで、LLMが単なる入力素材のみで判断するのではなく、「過去の履歴」に基づいたより高度なリレーション（`related`や`parent`）設定が可能になっています。
*   **JSONパースの堅牢性**: `clean_and_parse_json`の実装は、LLMから生成されるテキストデータ特有のエスケープシーケンスの問題を想定し、複数段階のクリーンアップ処理を経ています。これにより、データパイプラインの信頼性が大幅に向上しています。
*   **トランスフォーマーとしての役割**: 本コード全体は、単なるデータ処理スクリプトではなく、「ナレッジベースの知識（ルール）」「過去の経緯（DB）」「現在の素材（`content`）」を全て受け入れ、それらを統合して「次の状態（メタデータとノート）」を生成するための**「思考エンジン」**または**「知識昇華レイヤー」**として機能しています。
