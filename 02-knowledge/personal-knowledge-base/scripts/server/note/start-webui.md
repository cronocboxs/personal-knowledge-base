# start-webui 解析ノート

## 1. 概要・目的

この`start-webui.py`スクリプトは、Streamlitフレームワークを用いて、パーソナルナレッジベース（personal-knowledge-base）のコア機能群を統合的に提供するための最小限のWeb UIインターフェースです。

その主目的は、以下の2つの重要なプロセスをエンドユーザーやAIエージェントが容易に利用できるようにすることです。

1. **データインジェスト＆保存インターフェース:** 外部から取得した一次素材（ログ、メモ、データなど）を、定められた規約（`04-resources/`）に従って配置するためのインターフェースを提供します。
2. **知見検索・回答インターフェース:** 蓄積されたナレッジベース（`02-knowledge/`）の内容に基づき、質問に対する回答を生成するRAG（Retrieval-Augmented Generation）機能を提供します。

このWeb UIを通じて、単なる知識の参照に留まらず、「一次情報→知識ノート化→検索・利用」という情報ライフサイクル全体をシームレスに実行することが可能となっています。

## 2. 主要コンポーネント・機能

本スクリプトが実現している知的な処理パイプラインは、単なるUI表示に留まらず、複数の規約上の複雑なデータ処理ステップを自動化しています。

### 2.1. 知識の自動昇華パイプライン（AI自動昇華）
最も重要な機能です。外部から取り込まれた一次素材は、ただ保存されるだけでなく、AIによる高度な構造化処理を経ます。

*   **一次データ配置:** まず、入力されたデータは必ず`04-resources/`に一次データとして配置されます。
*   **メタデータ抽出・生成:** AI（LLM API）がテキストを分析し、規約ファイル`formatting.md`に厳密に基づいたYAMLフロントマター（`summary`, `tags`, `status`など）を抽出し、生成します。
*   **二層同期出力:** 生成されたメタデータと本文のペアが、以下の二つのファイル構造に同時に自動で書き込まれます。
    1.  `head/`: YAMLフロントマターのみ（検索効率最大化）。
    2.  `note/`: YAMLフロントマター + 実際の本文（完全なドキュメント）。

### 2.2. データ保存の柔軟な管理
データ保存機能は、ナレッジベースの構造を保ちつつ、運用上の柔軟性を提供します。

*   **サブディレクトリ指定:** ユーザーは任意のサブディレクトリ名を入力でき、そのディレクトリが`04-resources/`内に存在しない場合は、システムが自動的にそのディレクトリを生成します。

### 2.3. 質問回答（RAG）機能
保存された知識ベース全体を参照し、自然言語の質問に対して文脈に沿った回答を生成する機能を提供します。

## 3. 処理フローと実装ポイント

このWeb UIを支えるバックエンドのロジックは、単なるストリーム処理ではなく、**ナレッジベースの品質維持と規約遵守**に重点が置かれています。

1. **規約駆動のデータフローの強制:**
    *   スクリプトは、データがノイズとして扱われることを防ぐため、すべてのインプットデータに対して「一次資料としての配置（`04-resources/`）」→「構造化（AI昇華）」→「最終配置（`02-knowledge/`）」という一方向のフローを強制します。
2. **`GEMINI_API_KEY`を利用したメタデータ自動化:**
    *   環境変数にAPIキーを設定することで、YAMLメタデータの抽出（`summary`、`tags`など）プロセスをLLMにアウトソースし、人間による手動作業を極限まで減らしています。これは、ナレッジベースの「情報ノイズ化」を防ぐ上で最も重要な実装ポイントです。
3. **Streamlitによる体験の最適化:**
    *   技術的な処理（ファイルI/O、LLM API呼び出し、メタデータ生成）といった複雑なバックエンドプロセスを、エンドユーザーからは「フォームに入力し、ボタンを押す」という極めて直感的で簡単なWeb UI操作に抽象化・カプセル化しています。

要するに、本スクリプトは、複雑な情報工学的な処理を背後に秘めつつ、ユーザーフレンドリーなインターフェースとしてナレッジベースのエントランスポイントを担っています。
