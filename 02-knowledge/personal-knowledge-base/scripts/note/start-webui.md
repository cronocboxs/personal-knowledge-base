# start-webui 解析ノート

## 1. 概要・目的

このスクリプト (`start-webui.py`) は、個人ナレッジベースの運用における「**データ入力インターフェース層**」を提供するものです。

主な目的は以下の2点に集約されます。
1. **フロントエンド提供**: Streamlitを用いて、ユーザーが直感的に操作できるWeb UI環境を提供すること。
2. **データライフサイクル管理の自動化**: 単なるデータ閲覧・質問回答（RAG）だけでなく、入力された一次データを単に保存するだけでなく、定義されたナレッジベースの正規フロー（`04-resources/`への配置→AIによる昇華→`02-knowledge/`への二層出力）へと自動的に導くパイプラインのエンドポイントとなること。

## 2. 主要コンポーネント・関数

### Streamlit
*   **役割**: Web UIのフレームワーク。Pythonコードを用いてインタラクティブなWebアプリケーションを迅速に構築するために使用されます。
*   **実装の意義**: コマンドラインインターフェース（CLI）や単なるPython実行では実現が難しい、リソースの動的選択、ログ表示、ユーザーインタラクションの実現を可能にします。

### `04-resources/` (一次素材保存層)
*   **役割**: 全ての外部からの入力データや一次素材がまず通過する「受け皿」です。データが処理・分類される前に一時的に配置される場所です。
*   **特徴**: サブディレクトリの自動生成機能を持つため、ログや異なるプロジェクトのデータを構造的に分離して保存する規約を物理的に担保しています。

### AI自動昇華パイプライン (LLM API連携)
*   **役割**: 単なるテキストの保存（Storage）で終わらせず、情報を構造化されたナレッジ（Knowledge）に変換する最も重要なロジックです。
*   **具体的なタスク**:
    1.  `04-resources/`から一次データを取り出す。
    2.  AI（LLM）にテキストを渡し、`formatting.md`などの厳格な規約に基づいたYAMLメタデータ（Frontmatter）を抽出・生成させる。
    3.  メタデータと本文を同時に、`head/`（検索用）と`note/`（本文用）の二層構造に同期出力する。

## 3. 処理フローと実装ポイント

### 🚀 情報フローの担保
このWeb UIが提供する最も重要な機能は、情報が「メモ（Resource）」から「ナレッジ（Knowledge）」へと昇華するプロセス全体を強制的に実行させる点にあります。

1. **データ入力**: ユーザーがWeb UI経由でデータ（テキスト、ログなど）を入力します。
2. **一次格納**: 入力データはまず `04-resources/` の指定されたサブディレクトリにバイパスされ、追跡可能な形で配置されます。
3. **AIエンジン呼び出し**: Web UIの背後で、抽出されたデータがLLM API（例：Gemini）に送信されます。
4. **規約準拠の出力**: LLMは、指示書（プロンプト）と`formatting.md`の規約を厳守し、メタデータと抽出した本文を生成します。
5. **最終書き出し**: 生成されたコンテンツは、`head/` と `note/` の二層構造に同時に書き込まれ、ナレッジベース全体に反映されます。

### ✨ 技術的・運用的な重要ポイント
*   **自動化の強制力**: 単に「手動でファイルを置く」という運用を排除し、「AIエンジンを経由する」という必須ステップをWeb UIのプロセスフローとして組み込んでいます。
*   **二層同期の実現**: `head/` と `note/` の二層出力が自動で行われることで、情報の検索性（`head/`）と詳細な構造化（`note/`）という両方の要件を同時に満たしています。
*   **運用準備**: `GEMINI_API_KEY`の環境変数設定を推奨している点から、このシステムが特定のAIモデルのAPI連携を前提として構築されていることが明確です。
