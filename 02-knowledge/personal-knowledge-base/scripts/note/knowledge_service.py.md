# knowledge_service-py 解析ノート

## 1. 概要・目的

本サービスは、パーソナルナレッジベース（Knowledge Base）の中核を担う知識生成・管理エンジンであり、新規ナレッジを構造化し、リポジトリ全体に統合する役割を果たします。

最大の目的は、入力された一次情報（`04-resources/`）を単なるテキストで保存するのではなく、定義された規約（`formatting.md`など）に基づき、検索に特化したメタデータ（`head/`）と詳細な解説本文（`note/`）の「二層同期」という形式で、システムに書き起こすことです。

このサービスを介することで、AIエージェントが自律的かつ追跡可能な形で知識を蓄積し、ナレッジベース全体の検索性と利用効率を最大化します。

## 2. 主要コンポーネント・関数

本ファイルには、システム全体の規約遵守と情報流通を保証するための複数のユーティリティ関数が実装されています。

| 関数名 | 責務 | 処理内容 |
| :--- | :--- | :--- |
| `resolve_prompt_path` | **パス解決の正規化** | 指示書（プロンプト）の入力文字列を、コード実行環境、ルールディレクトリ、スキルディレクトリの複数の場所を探索し、最も正しい絶対パスに解決します。これにより、エージェントがどのルールを参照すべきかを迷うことなく特定できます。 |
| `get_available_prompts` | **プロンプト目録の生成** | `00-rules/prompts/` ディレクトリ配下の全てのMarkdownファイル名をリストとして取得します。エージェントが利用可能な指示書の一覧を参照する際に使用されます。 |
| `load_rule_docs` | **規約のコンテキスト統合** | システムの運用に必須な全規約ファイル（`AGENTS.md`, `formatting.md`, `workflow.md`, `agent-behavior.md`）を一括で読み込み、単一の巨大なプロンプトコンテキストとして統合します。これにより、LLMに対する指示の抜け漏れを防ぎます。 |
| `get_existing_notes_context` | **知識ベースの参照コンテキスト構築** | SQLiteデータベース（`knowledge_index`）に接続し、既存のナレッジノートのタイトル、関連パス、概要（`summary`）を抽出し、LLMに参照可能な情報として渡します。これにより、エージェントは既存の知識構造を意識した記述が可能になります。 |
| `generate_knowledge_files` | **知識生成のメインロジック** | 新規知識の生成プロセス全体を統括します。以下の「メタデータ抽出（PASS 1）」と「ファイル同期出力」のフローを制御します。 |

## 3. 処理フローと実装ポイント

### 🧠 知識生成のプロセス（`generate_knowledge_files` のフロー）

本サービスは、以下の3段階の構造化されたフローでナレッジを生成します。

1.  **コンテキスト準備**: 処理開始前に、`load_rule_docs()`によって全規約を、`get_existing_notes_context()`によって既存の知識マップを準備し、AIエージェントが判断するための全コンテキストを構築します。
2.  **メタデータ抽出（PASS 1）**:
    *   LLMに対し、提供されたすべての規約と既存ナレッジを渡します。
    *   最も重要なステップであり、単なる内容抽出ではなく、`formatting.md`で厳密に定義されたYAML Frontmatter属性（`summary`, `tags`, `parent`, `children`など）をJSON形式で抽出・判定するタスクを実行します。
    *   これにより、記事の本文が完成する**前から**、知識グラフ上の位置づけ（親、子、関連）が確定します。
3.  **知識ファイル出力（二層同期）**:
    *   解析が完了した後、決定されたメタデータと本文を、`head/`（YAMLのみ）と`note/`（YAML+本文）の**両方に同期**して書き出します。
    *   この「二層同期」構造こそが、ナレッジベースが検索（`head/`）と閲覧（`note/`）の両面で最適化される根幹です。

### ✨ 重要実装ポイントと設計思想

*   **自己修正・検証の仕組み**: `clean_and_parse_json`関数が導入されている通り、LLMの出力をそのまま信用せず、JSON形式の堅牢なパース処理を通して、AIの出力を安全かつ信頼性の高いデータ構造に強制的に変換する仕組みが採用されています。
*   **規約への強制的な準拠**: メタデータ抽出時に、常に`formatting.md`に準拠したJSON出力を求め、AIの出力を形式面からガバナンス下に置いています。
*   **タスク管理の一元化**: `task`プロパティをメタデータに組み込むことで、「次に何をすべきか」という追跡対象をファイル内の本文ではなく、構造化されたメタデータによって管理し、システム的な実行フローを保証しています。
