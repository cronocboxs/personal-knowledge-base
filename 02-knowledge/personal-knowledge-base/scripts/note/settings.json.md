# settings-json 解析ノート

## 1. 概要・目的

本ファイル（`settings-json`）は、アプリケーションが利用する複数の大規模言語モデル（LLM）の接続情報や、デフォルトで採用するモデルのバージョンを集中管理するための設定ファイルです。

システム全体におけるLLMの振る舞いや、どのプロバイダー（Gemini, Ollamaなど）を経由してAPIコールを行うかを切り替えるための「マスター設定」として機能します。

現在の設定では、開発環境またはローカル環境での動作を前提とし、`default_provider`を`Ollama (Local LLM)`に設定している点が特徴的です。

## 2. 主要コンポーネントと構造

本JSON構造は、プロバイダーごとの設定をネストされたオブジェクトとして定義しています。

### `default_provider`
*   **値**: `"Ollama (Local LLM)"`
*   **責務**: システムが最初に使用を試みる、または推奨するLLMの接続先を指定します。現在の設定では、ローカルで稼働するOllamaサービスがデフォルトとされています。

### `gemini`
*   **責務**: Google Gemini APIの接続設定を保持します。
*   **`default_model`**: 現在のデフォルトモデルとして`gemini-3.5-flash-lite`が指定されています。
*   **`available_models`**: このプロバイダーから利用可能なモデル名のリストを保持します。

### `ollama`
*   **責務**: ローカル実行環境で動作するLLMを管理するための設定です。
*   **`default_model`**: デフォルトで使用するOllama上のモデル名を指定しています（例: `gemma4:e4b-it-q4_K_M`）。
*   **`endpoint`**: Ollamaサービスがリッスンしているローカルのネットワークアドレスとポートを定義しています（`http://localhost:11434`）。

## 3. 処理フローと実装ポイント

1.  **接続プロバイダーの切り替え**: アプリケーションコード内では、この設定ファイルを読み込み、実行環境やユーザー設定に基づき、どのプロバイダー（`gemini`または`ollama`）の接続情報を利用するかを決定します。
2.  **ローカル優先設計**: `default_provider`を`Ollama (Local LLM)`に設定していることから、本システムは本番環境やクラウドAPIコールを主とする場合でも、開発・テスト時にはローカルリソースを活用し、レイテンシやコストを抑える設計思想が強く反映されています。
3.  **モデル名の管理**: 各プロバイダーのモデル名がコード内にハードコーディングされるのではなく、この設定ファイルに一元化されているため、将来的に利用するモデルを変更する際も、このファイルのみの更新で対応できる高い拡張性と保守性が確保されています。
