# start-webui-py 解析ノート

## 1. 概要・目的

本スクリプト `start-webui-py` は、パーソナルナレッジベース（PKB）全体の情報を視覚的に管理し、ユーザーがAIエージェントやローカルLLM（Ollama, Gemini）を利用してナレッジを操作するためのWebインターフェース（WebUI）を構築することを目的としています。

PythonのStreamlitフレームワークを用いてGUIを構築しており、単なる表示ツールに留まらず、知識の探索（エクスプローラー風ツリー）と、その知識を活用した入力・編集（フォーム表示）をシームレスに行うためのメインのポータル兼アプリケーションレイヤーとして機能しています。

このWebUIを通じて、ユーザーは以下のような操作が可能になります。

1.  知識ベースのカテゴリ構造の閲覧。
2.  利用するLLMプロバイダ（OllamaまたはGemini）の選択と設定。
3.  知識ファイルやリソースファイルの選択と、その内容をフォーム上で確認・編集。

## 2. 主要コンポーネント・関数

### Streamlit (st)
アプリケーションの基盤であり、WebUIの構築、セッション状態の管理 (`st.session_state`)、サイドバーでのUI要素配置（`st.sidebar`）、インタラクティブな要素（`st.radio`, `st.button`, `st.expander`）の提供を担当します。

### `get_knowledge_categories()`
知識ベースディレクトリ (`KNOWLEDGE_DIR`) の内容を走査し、主要な知識カテゴリ（ディレクトリ名）のリストを返します。これにより、UIのサイドバーにエクスプローラー風のツリー構造の根幹となる分類を提供します。

### `get_ollama_models()`
システム環境のローカルLLMリソースを動的に把握するための関数です。`subprocess.run(["ollama", "list"])` を実行し、現在ローカルにデプロイされている利用可能なOllamaモデル名をリストアップします。これにより、利用可能なモデルの選択肢をUIにリアルタイムで反映させています。

### `render_explorer_tree(dir_path, ...)`
このWebUIの最も重要な表示ロジックを担います。指定されたディレクトリパスを再帰的に走査し、以下のインタラクティブなツリー構造をサイドバーに描画します。
*   ディレクトリは`st.expander`で折りたたみ可能に。
*   ファイルはクリック可能なボタン（`st.button`）として配置され、クリックされるとファイルの内容をフォームエリアにロードするトリガーとなります。

## 3. 処理フローと実装ポイント

### 処理フロー

1. **初期化**: スクリプト実行時、`st.session_state`が初期化されます。これは、WebUIの状態（例：どのファイルが開かれているか、どのLLMが選択されているか）を保持し続けるために不可欠な処理です。
2. **モデル選択（サイドバー上部）**: ユーザーはLLMプロバイダをラジオボタンで選択します。
3. **プロバイダ設定**:
    *   **Gemini選択時**: APIキーのロード状況をチェックし、Geminiの利用可能性をフィードバックします。
    *   **Ollama選択時**: `get_ollama_models()`を呼び出し、利用可能なローカルモデルをドロップダウンに表示し、エンドポイントを設定させます。
4. **エクスプローラー描画（サイドバー下部）**: `render_explorer_tree`が知識ベース全体をスキャンし、ディレクトリとファイルをボタンとして描画します。
5. **コンテンツロード**: ユーザーがファイルをボタンでクリックすると、`load_file_to_form`が実行され、ファイルのパスが取得され、ファイルの内容がメインのフォーム（入力/閲覧エリア）に表示されます。

### 重要実装ポイント

#### ① ステート管理の徹底
StreamlitはWebアプリケーションフレームワークであり、スクリプトの実行は「リクエスト単位」で行われます。そのため、サイドバーでLLMの選択や、メインエリアで開いたファイル情報といった状態を永続化するために、`st.session_state`を利用することが最も重要です。この状態管理が、マルチステップのユーザー操作を可能にしています。

#### ② モジュール性・抽象化されたAI接続
本スクリプトは、LLMの利用方法（OllamaかGeminiか）を切り替えるための抽象化レイヤーを提供しています。AIモデルの選択と設定がサイドバーに統合されているため、バックエンドでどのLLMクライアント（`llm_client`）を呼び出すかというロジックを、UI層から綺麗に分離しています。

#### ③ 知識ベースの動的な可視化
ファイルシステムの走査（`os.listdir`, `os.path.isdir`）とStreamlitのUI要素を組み合わせることで、静的なドキュメントリストではなく、インタラクティブに展開・折りたたみ可能な「エクスプローラー」の体験を提供しています。これは、膨大な知識ベース構造におけるユーザーのナビゲーション効率を劇的に向上させます。
