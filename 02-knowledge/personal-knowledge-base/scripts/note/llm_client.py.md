# llm_client-py 解析ノート

## 1. システム概要・目的

本スクリプト（`llm_client-py`）は、Python環境から複数の異なる大規模言語モデル（LLM）プロバイダー（Google Gemini API および Ollama ローカル環境）に対して、汎用的にプロンプトを送信し、応答を取得するための抽象化レイヤー（クライアント関数）を提供することを目的としています。

LLMの利用環境（クラウドAPIかローカルモデルか）を切り替えることで、単一の関数呼び出しから複数のモデルへの接続を試行でき、開発の効率性と柔軟性を高めています。

## 2. 主要コンポーネント・関数

### `call_llm` 関数

この関数が本スクリプトの中心的な役割を果たします。LLMへの通信処理全体をカプセル化しており、実行環境とモデル名に応じて処理フローを動的に変更します。

**関数シグネチャ:**
```python
call_llm(
    prompt: str,
    llm_provider: str = "Ollama (Local LLM)", # 利用するプロバイダー（Gemini/Ollama）
    gemini_model: str = "gemini-2.5-flash",  # Gemini利用時のモデル名
    api_key: str = "",                      # Gemini利用時のAPIキー
    ollama_model: str = "qwen2.5:1.5b",    # Ollama利用時のモデル名
    ollama_url: str = "http://localhost:11434" # OllamaのAPIエンドポイント
) -> str:
```

**主な機能:**
1. **ロジック分岐**: `llm_provider` の値に基づき、Gemini APIへのアクセスロジックとOllama APIへのアクセスロジックを分離して実行します。
2. **リトライメカニズム**: API通信の堅牢性を確保するため、最大3回のリトライが実装されています。
3. **指数バックオフ（Exponential Backoff）**: HTTP 503 Service Unavailable エラーが発生した場合、待機時間を指数関数的に増加させながら（2秒, 4秒, ...）再試行を行います。

## 3. 処理フローと重要実装ポイント

### A. 処理フロー（通信クライアントの動作）

1. **入力検証**: Geminiの場合、APIキーの存在を最初にチェックします。
2. **APIリクエストの構築**: 選択されたプロバイダー（GeminiまたはOllama）の指定されたエンドポイント（URL）と、要求ボディ（JSONペイロード）を準備します。
3. **リトライループ実行**: `for attempt in range(max_retries)` のループに入り、APIコールを実行します。
4. **成功/失敗判定**:
    * 成功した場合: 応答データからLLMのテキスト結果を抽出し、返却します。
    * 失敗した場合（HTTP 503）: リトライ可能回数内であれば、待機時間（`retry_delay`）を倍増させて再試行します。
    * 失敗した場合（その他の致命的なエラー）: 例外を再発生させ（`raise e`）、上位レイヤーにエラーを通知します。

### B. 重要実装ポイント

#### 1. 抽象化レイヤーとしての設計
Gemini (HTTPS/JSON API) と Ollama (HTTP/JSON API) という構造が全く異なる二つのシステムへの接続ロジックを、一つの関数内で`if-else`構造とリトライ機構で吸収している点が最大の設計上の強みです。これにより、上位のビジネスロジックは通信先の違いを意識する必要がなくなります。

#### 2. 堅牢なエラーハンドリングとリトライ
* **リトライ回数の設定**: `max_retries = 3` は、一時的なネットワーク混雑やサービス負荷による一時的な障害に対応するための基本的なガードレールとして機能します。
* **待機時間の戦略**: 503エラーの場合に待機時間を指数関数的に増やす（`retry_delay *= 2`）アプローチは、API側への過度な負荷をかけすぎず、サービス回復を待つためのベストプラクティス（指数バックオフ）を採用しています。

#### 3. 環境依存性の管理
* GeminiのAPIキーは、外部ファイル（`01-private/gemini_api_key.txt`）から取得することを期待しており、機密情報管理のフローを意識した設計となっています。
* クライアントライブラリとしての利用を前提としており、外部依存関係（`urllib.request`, `json`, `time`）が明記されています。
