# 📄 config.py - システム設定・依存関係管理

## 🧠 役割と概要
`config.py` は、`scripts/server/` 内の複数のサービスファイル（`knowledge_service.py`, `llm_client.py` など）が共通して依存する、システム全体の環境設定、APIキーの管理、およびプロジェクトルートへの絶対パス定義を一元的に担うコアな設定ファイルである。このファイルを通じて、アプリケーションの動作環境（データベースパス、外部APIエンドポイント）が決定される。

## 📁 主要な責務と機能詳細

### 1. プロジェクト内部パスの定義
このファイルは、`os.path.abspath` を用いて、プロジェクトルート（`scripts/server/` の2階層上）を基準とする一連の絶対パス（`CONFIG_PATH`, `PRIVATE_DIR`, `RULES_DIR`, `KNOWLEDGE_DIR`, `DB_PATH` など）を定義している。これにより、コードのどの場所から実行されても、参照するファイルやディレクトリのパスが常に一貫性を保つことが保証されている。

### 2. 設定値の読み込みと初期化 (`load_config`)
- **機能:** `settings.json` から設定を読み込む。
- **ロジック:** 最初に指定された `CONFIG_PATH` のファイルをチェックし、存在すればJSONとしてロードする。
- **フォールバック:** ファイルが存在しない場合、または読み込みに失敗した場合、`DEFAULT_CONFIG` 定義に基づいたデフォルト設定（ローカルLLMプロバイダー、Geminiの初期モデル名など）をファイルに書き込み、それをデフォルトとして利用する。

### 3. 外部認証情報の取得 (`get_gemini_api_key`)
- **機能:** Gemini APIキーを安全に取得し、返す。
- **ロジック:** 設定ファイル構造のベストプラクティスに基づき、複数の候補となるファイルパス（`01-private/gemini_api_key.txt`, `01-private/gemini-api-key` など）を巡回して確認する。最も早く見つかった、空でないキーを返すため、秘密情報の配置場所の柔軟性に対応している。環境変数 (`os.environ.get("GEMINI_API_KEY")`) も最終的なフォールバックとして考慮される。

## 🧭 データフローと依存関係
*   **Input:** 実行時のシステム環境、およびプロジェクト直下の `01-private` ディレクトリ内の認証情報、`settings.json`。
*   **Output:** システム全体で使用されるグローバルな定数群（パス、モデル名など）。
*   **依存先:** プロジェクト構造そのものに強く依存しており、特に `01-private` (秘密情報), `00-rules` (規約), `02-knowledge` (知識ベース) ディレクトリが必須である。

## 💡 技術的考察
このファイルは単なる設定ファイル以上の「環境設定レイヤー」としての役割を担っている。パスの再構築ロジック(`os.path.join(SCRIPT_DIR, "../../")`)を理解することが、このモジュール全体を理解する鍵となる。全てのAPI利用や知識永続化の起点となる絶対路径がここで確立される。
