# [server_config] config.py - Detailed Technical Analysis

## 1. 構造と責務
このファイルは、アプリケーションの初期設定値、絶対パス定義、および外部ファイル（`settings.json`）の読み込みロジックを負っています。単なる設定値の集積ではなく、プロジェクト全体の位置関係をOSレベルで固定し、他のモジュールがパスエラーを起こさないようにするための「根幹システム」としての役割を果たしています。

**重要構造:**
*   **絶対パス定義パス群 (PROJECT_ROOT, CONFIG_PATH, ...)**: `os.path.join(SCRIPT_DIR, "../../")` を使用して、実行場所から常にリポジトリルート (`PROJECT_ROOT`) を参照する仕組みが、このファイル設計の心臓部です。これにより、どのサーバーディレクトリからスクリプトを実行しても正しい設定や知識ベースのパスに到達できます。

## 2. 主要な関数とロジックフロー

### 2.1. `load_config() -> dict`
**機能**: 設定ファイルの読み込みと初期化。
**詳細フロー**:
1.  `CONFIG_PATH` (`settings.json`) の存在確認。
2.  **[Hit]** 存在する場合: `json.load(f)` を試行し、設定値を返却します。
3.  **[Miss]** 存在しない、または読み取りエラーの場合: `DEFAULT_CONFIG` (ハードコードされたデフォルト値) を含む新しい `settings.json` ファイルを現在のパスに書き込み（初期化）、そのデフォルト値を返却します。
**安全性機構**: この処理は、設定の読み込み失敗時にもアプリケーションがクラッシュしないように、必ずデフォルト設定で続行可能であることを保証します。

### 2.2. `get_gemini_api_key() -> str`
**機能**: 複数の候補場所からAPIキーを探索し、取得する。
**詳細フロー**:
1.  `PROJECT_ROOT/01-private/` 以下にある、特定の名前 (`gemini_api_key.txt`, `gemini-api-key`, `api_key.txt`) を持つファイル群を順次チェックします。
2.  ファイルが見つかった場合、その内容を読み取り、最初の空でない値（キー）を返却します。
3.  全てのファイル検索に失敗した場合、環境変数 `GEMINI_API_KEY` を最終的なフォールバックとして使用します。
**設計意図**: 認証情報の配置場所を正規化し、誰がどの変数を使うかに関わらず、共通の取得インターフェースを提供しています。パスの検索順序は、開発上の慣習や優先度に基づいています。

## 3. 技術的考察
*   **依存関係**: `os`, `json` (Python標準ライブラリ)。
*   **アーキテクチャ上の役割**: Configuration Source of Truth (単一の真実の源)。全てのモジュールが依存する最上位レイヤーのデータ定義を提供することで、設定値に関する潜在的な衝突（Conflict）を防いでいます。
*   **品質保証**: ファイルパスの処理に `os.path.join` を使用することで、OS固有のパス区切り文字の問題を抽象化し、クロスプラットフォーム対応を確保しています。
