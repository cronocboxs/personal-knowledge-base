# web-php 解析ノート

## 1. 概要・目的

本ファイルは、ウェブアプリケーションにおける全てのクライアント要求（リクエスト）の入り口となるメインルーティングファイル（`web.php`）です。Laravelフレームワークのルーティング機能を使い、アプリケーションの全ての機能領域（例：ホーム画面、API、ユーザー領域、管理画面）への経路（Route）を定義し、管理しています。

このファイルは単なるルーティング定義に留まらず、異なる機能群（個人領域、サービス領域、システム管理領域など）がそれぞれ独立したファイルとして存在し、本ファイルで`require_once`によって結合される**モジュール化された構造**を持つことが最大の特徴です。

## 2. 主要コンポーネント・関数

### 2.1. 環境依存の強制処理
*   **`App::environment('production')`**: 現在の実行環境が本番（`production`）またはステージング（`staging`）であるかを判定します。
*   **`URL::forceScheme('https')`**: 上記の環境判定に基づき、HTTPSの使用を強制する設定を行います。これは、本番環境でのセキュリティ標準化のため必須の処理です。

### 2.2. 基本ルーティングの定義
*   **`Route::get('/', ...)`**: トップページ（ルートURL）のGETリクエスト定義。
*   **`Route::group([...])`**: 共通のプレフィックスやミドルウェア（認証状態など）を複数のルートに適用するために使用されるグループ定義。
    *   `webhock`: Webhook処理用のルートグループ。
    *   `test.`: ローカル環境でのみ有効なテスト用ルートグループ（`middleware' => ['env:local']`）。

### 2.3. モジュールローディング（結合処理）
ルーティングファイルの後半に続く複数の`require_once`ステートメントが最も重要です。これらはアプリケーションを機能単位（ドメイン）で分割し、それぞれのルーティングを本ファイルに統合しています。

| ファイルパス | 担当領域 | 役割の分類 |
| :--- | :--- | :--- |
| `public/index.php` | SaaS公開領域 | アプリケーションの初期起動と基本的な公開ルートを担当。 |
| `web/api.php` | 共通インフラ | 認証やログイン前段階で共通して必要となるAPIやインフラ関連のルーティングを定義。 |
| `web/login.php` | 認証 | ログイン処理を担当するコントローラ周りのルート。 |
| `web/user.php` | 個人領域 | ログイン後のユーザー個人のデータやページに紐づくルート。 |
| `web/provier.php` | Provider領域 | プロバイダー（外部連携サービス）関連のルート定義。 |
| `web/service/provider.php` | Provider領域 | プロバイダー選択が必須となるサービス関連のルート。 |
| `web/service.php` | 業務アプリ | 実際の業務ロジック（アプリケーションのコア機能）に紐づくルート。 |
| `web/system.php` | システム関連 | アプリケーションの管理画面、システム設定など、バックエンド向けのルート。 |

## 3. 処理フローと実装ポイント

### 3.1. 初期フロー
1.  **環境チェック**: 実行環境が本番/ステージングの場合、HTTPS強制が実行されます。
2.  **基本ルート登録**: トップページ、および標準的な404/403エラーハンドリングルートが最初に定義されます。
3.  **特殊ルート登録**: Webhookやテスト用など、特定の条件（グループ化）を持つルートが登録されます。

### 3.2. 構造上の重要ポイント
*   **関心の分離（SoC）の徹底**: 本ファイルは**「どの機能が、どのURLに配置されているか」**というマッピング（地図）の役割に徹し、実際のルーティングコード（ロジック）は全て外部ファイルに分離されています。
*   **実行順序による依存関係**: このファイルに記載された`require_once`の実行順序が、アプリケーションの初期化とルーティングのロード順序を決定づけています。基本的な認証基盤（`web/api.php`など）が先にロードされ、その後に個別機能（`web/user.php`など）が積み上げられる構造です。

### 3.3. まとめ
この`web.php`は、単なるルーターファイルではなく、**アプリケーション全体の機能モジュールを統括し、各機能がどのURLでサービス提供を開始するかを定義する「マスタールーティング定義書」**として機能しています。新しい機能を追加する際は、まずその機能に対応する外部ファイル（例：`web/new-feature.php`）を作成し、この本ファイルに`require_once`で組み込むのが標準的な運用フローです。
