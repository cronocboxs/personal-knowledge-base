# 情報ライフサイクル・フロー規約 (Workflow Rules)

本リポジトリにおける情報の段階的昇華およびナレッジ解析の基本運用フローです。

---

## 1. 基本情報処理ステップ

1. **Input**: 一時メモや外部素材、一次情報を `04-resources/`（バイナリは `06-storage/`）に配置する。
2. **Digest & Facting**: `04-resources/` を分析・抽出・整理し、知見ノートとして `02-knowledge/` に書き起こす。
3. **Action**: 発生したタスク・追跡対象は `02-knowledge/` 内の `head` メタデータ（`task`）で一元管理する（個別指示のみ `05-todo/` を使用）。
4. **Output**: `02-knowledge/` を元に再構成・執筆し、`03-output/` で成果物を生成する。
5. **Archive**: 完了した成果物・一次データは `06-storage/` へ移動し、不要物は `99-trash/` へ移動する。

---

## 2. ナレッジ解析・深掘りサイクル (Target Selection & Evolution)

AIエージェントが自律的にナレッジを構築・更新する際は、以下のサイクルに従うこと。

1. **スクリーニングと対象選定**:
   - `02-knowledge/<リポジトリ名>/head/` 配下の YAML メタデータのみを高速走査する。
   - `phase: 0`（未着手）または Frontmatter 内の `task` に未消化項目が存在するファイルを最優先で選定する。

2. **ピンポイント解読と追記**:
   - `task` に指定された具体的なファイル・関数名のみを `04-resources/` からピンポイントで閲覧し、最深部ロジックをノート本文に書き込む。

3. **先行宣言 (head-only Stub)**:
   - 解析中に未定義の関連ドメインを発見した場合、現在のノートの `parent` / `children` / `related` にノート名を追加する。
   - 実ファイル（`note/`）が存在しない場合、**`head/` 配下のみに `phase: 0` の YAML ファイルを作成**する。

4. **二層同期出力 (Dual Output)**:
   - 解析完了後、`head/<ファイル名>.md`（YAMLのみ）と `note/<ファイル名>.md`（YAML＋本文）を完全同期して更新・出力する。
   - 消化したタスクは `task` から削除し、全タスク消化時に `phase` を更新する。

5. **インデックス同期**:
   - 処理完了時は `./scripts/run-markdown-index.sh 02-knowledge/<リポジトリ名>` を実行して同期する。

---

## 3. API レートリミット回避ルール (15 RPM 制限対策)

- ツール呼び出し（ファイル閲覧・検索等）を **8〜10 回** 実行した段階で、一時的にツール実行を停止し、思考出力のみで待機姿勢をとること。
- エラー `Rate limit exceeded` や `429` が発生した場合は、指示された指定待機時間に +5 秒を加算して待機リトライすること。
