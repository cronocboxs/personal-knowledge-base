# ファイル命名・記述・メタデータ規約

AIエージェントがファイルを作成・更新する際は、本規約に従ってください。

---

## 1. ファイル命名規則

* 原則 `kebab-case.md`（例: `laravel-referer-check.md`）または日付プレフィックス `YYYY-MM-DD-title.md` を使用すること。

## 2. メタデータ (YAML Frontmatter)

* 新規Markdownファイルの先頭には、必ず以下のメタデータを付与すること。

```yaml
---
created: YYYY-MM-DD
tags: [tag1, tag2]
status: draft # draft | active | archived
unexplored_domains: [] # 機能一覧配列
---
```

* **非破壊原則**: ファイルの直接削除（`rm`）は禁止。不要ファイルは `99-trash/` へ移動
* **スクリプト活用**: 定型・バッチ処理は `scripts/` 内の既存コードを利用するか新規スクリプトを作成

## 3. 解析対象の範囲

* ソースコード（言語問わず主要なロジック）
* 設定ファイル（`package.json`, `Cargo.toml`, `pyproject.toml`, `Dockerfile`, `docker-compose.yml` 等）
* CI/CDパイプライン（`.github/workflows` 等）
* 既存の `README.md` やドキュメント類
* その他、全てのテキスト類

## 4. 出力するドキュメントの構成

特に指定がない場合は、以下の構成でMarkdownを出力してください。

1. **プロジェクト概要**
  - このプロジェクトは何をするものか（目的・主な機能）
  - 対象ユーザー・ユースケース

2. **技術スタック・インフラ構成**
  - 使用言語、フレームワーク、主要ライブラリとそのバージョン
  - 外部サービス、コンテナ、インフラの依存関係

3. **ディレクトリ構造と責務**
  - 主要なフォルダ・ファイルのツリー表示
  - それぞれが持つ役割（アーキテクチャパターン：Clean Architecture, MVCなど）の説明

4. **セットアップ・起動手順**
  - 必要な前提ツール（Node.js, Docker等）
  - インストール、環境変数の設定、ビルド・実行コマンド

5. **主要な機能・設計方針**
  - コアロジックの仕組み、データフロー
  - 特筆すべき設計上の工夫や制約

## 3. 執筆のルール

* 事実に基づき、コードから読み取れる内容のみを記述してください（推測で書かない）。
* 専門用語や独自の設計概念には簡潔な説明を加えてください。
* メンテナンス性を考慮し、常に「生きたドキュメント」となるよう正確性を重視してください。
