# エージェント行動規範・連携規約

## 1. 実行権限

* **自律実行**: 単一ファイルの作成・更新・整理・メタデータ付与、規約改変。
* **要承認**: ディレクトリ構造変更、複数ファイルの一括移動・削除・置換。
* **完了報告**: 「変更ファイルパス」と「変更内容」を簡潔に出力。

## 2. ルール改変とログ記録 (Rule Modification)

* **`00-rules/` 改変**: システムの深掘り性能や運用性向上のための編集を自律許可。
* **ログ保存先**: 改変理由・背景・変更差分を `04-resources/logs/rule-change-YYYYMMDD.md` へ新規出力。
* **例外規定**: `04-resources/` は原則読み取り専用だが、本変更ログ（`04-resources/logs/`）の新規作成・追記出力のみ例外的に許可する。

## 3. 記述最小化原則 (Minimal Context Standard)

* **存続基準**: 「その1行の削除によりAIの行動・判断に変化が生じるか」。
  * 行動変化あり ➔ 保持
  * 行動変化なし（説明・背景・冗長ログ） ➔ 削除（背景は `04-resources/logs/` へ退避）
* **ナレッジノートでの適用**: 重複する実行ログは残さず、最新かつ最深部のコード構造記述へと内容を統合・上書き補全すること。

## 4. 効率的な情報探索・シェル実行抑止 (Minimal Shell Standard)

* **`ls` コマンドの実行禁止**: ディレクトリ一覧確認や目的のファイル検索のために `ls -1` / `ls -l` などのシェルコマンドを実行することは原則厳禁。
* **2段階インデックス参照フローの徹底**:
  1. **全体マップ参照**: まず `02-knowledge/global-index.json` を読み込み、目的の階層（例: `02-knowledge/subsidies`）に対応する `index.json` のパスを確認する。
  2. **階層インデックス参照**: 該当階層の `index.json` を読み込み、対象ファイルの相対パスをピンポイントで特定して直接開く。
* **インデックス更新**: ファイルを新規作成・移動・削除した場合は、`scripts/run-markdown-index.sh <path>` を実行してインデックスを更新すること。
* **目的**: シェルコマンド実行の往復によるトークン消費とコンテキスト膨張を防止し、API運用コストを最小化する。
