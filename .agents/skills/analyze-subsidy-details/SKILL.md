# 役割

`04-resources/subsidies/subsidy-list-YYYYMM.md` に記載された補助金・助成金の概要情報をインプットとし、**「パッと見ではわからない抽象的な申請条件」を徹底的に解読・具体化**する。
公的公募要領・FAQ・取扱マニュアル等の一次情報を深く探索し、具体的な金融機関名や専門家の定義、推測補全（推測である旨を明示）を交えて `02-knowledge/subsidies/` 配下に解像度の高いナレッジノートを作成する。

---

## 前提条件（共通ルールの確認）

- 作業開始時に、リポジトリルート直下の `AGENTS.md` および `00-rules/workflow.md` を必ず読み込むこと。

---

## 条件・解読の重要着眼点（深掘りチェックリスト）

抽象的な表現を見つけた場合、以下の観点で一次情報（公募要領・FAQ・手引きPDFなど）を追尾・解読すること。

1. **金融機関の解読**:
   - 単に「取扱金融機関」とある場合 ➔ どの銀行・信用金庫・公庫が対象か（例: 東京都中小企業制度融資の場合、都内指定金融機関、〇〇信用金庫、日本政策金融公庫など具体名を抽出）。
2. **「専門家」の定義と資格**:
   - 単に「専門家」とある場合 ➔ 中小企業診断士、税理士、公認会計士、認定経営革新等支援機関（認定支援機関）、行政書士など、どの資格・機関を指すのかを明記。
3. **「事業計画書・書類」の具体内容**:
   - 単に「事業計画書の作成」とある場合 ➔ どのフォーマット、どのような指標（付加価値額年率3%増加など）が必須か。
4. **推測補全ルール**:
   - 一次情報にも明記されていないグレーゾーンや実務上の通例については、**「💡 AI推測・実務上の想定: 〜」** と明記した上で、申請時の注意点や考えられる具体的な条件を論理的に推測記載すること。

---

## 仕事

- **実行手順**:
  1. **解析対象の選択**:
     - `04-resources/subsidies/subsidy-list-YYYYMM.md` から、まだ `02-knowledge/subsidies/` 内に詳細ノートが作成されていない制度を1件選択する。
  2. **一次情報の最深部探索（公募要領・FAQ・ガイドライン）**:
     - 制度の公式一次情報URL（および関連する公募要領PDF、FAQページ）にアクセスし、申請条件の詳細ルールを読み込む。
  3. **条件の深掘り・解読・推測補全**:
     - 上記「着眼点」に沿って、あいまいな条件を具現化する。
  4. **ナレッジノートの出力**:
     - `02-knowledge/subsidies/<制度名のkebab-case>.md` に構造化フォーマットに従って保存する。

- **やらないこと**:
  - 概要ページに書かれている抽象的な文面（例: 「専門家の助言が必要」）をそのままコピペして終わること。
  - 公募要領やFAQまで確認せずに「不明」と決めつけること。

- **絶対にやってはならないこと（AIのサボり対策）**:
  - 推測で書いた部分に「推測である旨」を記載せず、公式の確定仕様かのように捏造すること（推測は必ず「💡 推測」と明記すること）。

- **入力**:
  - 収集済みリスト: `04-resources/subsidies/subsidy-list-YYYYMM.md`
  - 公式一次情報URL（Webページ、公募要領PDF、FAQ等）

- **出力先**:
  - 詳細ナレッジノート: `02-knowledge/subsidies/<制度名のslug>.md`

- **終わりの条件**:
  - **1回のセッションにつき10件**の補助金制度について最深部まで解読を完了し、ファイル出力が完了した時点。
  - 未解析の制度が 0 件になった場合。
  - 処理・ファイル更新・コミット完了後はセッションを終了すること。

- **止まる条件**:
  - APIレートリミット（429等）が発生し、待機後のリトライを **5回連続で失敗** した場合。
  - または、未解析の制度が 0 件になった場合。
