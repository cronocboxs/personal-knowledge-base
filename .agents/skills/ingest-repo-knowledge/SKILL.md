# 役割

`04-resources/git-repository/<リポジトリ名>/` 内のソースコードを読み込み、画面操作（ボタン押下、入力、ログイン等）に対する**具体的一連の挙動（UI変化・データ推移・裏の処理）**を人間やAIがマニュアル・仕様書として出力できる解像度で `02-knowledge/<リポジトリ名>/` 配下に蓄積し、Git コミットまで完了させる。

---

## 前提条件（共通ルールの確認）

- 作業開始時に、リポジトリルート直下の `AGENTS.md` および `00-rules/workflow.md` を必ず読み込み、そこに記載された「絶対遵守ルール」「ディレクトリ編集ポリシー」「ナレッジ育成ルール」に従うこと。

---

## 知識進化（Knowledge Evolution）判定規則

`02-knowledge/<リポジトリ名>/` 内のノートの Frontmatter (`phase`) を更新する際は、**画面・ユースケース単位で操作手順と裏の処理が解読できているか**を基準に判定すること。

| Phase | 判定基準 | 今回実行すべき解析・蓄積タスク |
| :--- | :--- | :--- |
| **未作成** | ファイルが存在しない | **Phase 1 (画面・機能一覧の把握)**: 画面（Vueコンポーネント/Blade）、フォーム、主要ボタン、ルーティングの全目録化 |
| **Phase 2** | 画面一覧はあるがボタン単位の挙動がない | **Phase 2 (操作トリガー別イベントトレース)**: 各画面の入力項目や**ボタン押下時のイベント（onClick等）から、送信パラメータ、Controller/ServiceでのDB更新、画面の遷移・レスポンス変化**をトレースして追記 |
| **Phase 3** | 操作挙動は書かれているが例外や連携がない | **Phase 3 (例外系・ドメイン間連動の補全)**: バリデーションエラー時の画面表示、権限によるボタン非表示、他機能（勤怠打刻によるシフト自動変更等）への連動影響の解読 |

---

## 仕事

- **実行手順**:
  1. **画面・操作要素の特定**:
     `resources/js/Pages/` や `resources/views/` のファイルを開き、画面上の**ボタン（`<button>`, `@click`）、フォーム（`v-model`, `submit`）、入力項目**をすべて抽出する。
  2. **イベントの処理追跡（ボタン押下〜結果表示まで）**:
     抽出したボタン等から呼ばれる JS 関数（`Inertia.post`, `axios`, Composable）を追いかけ、送信先 Route ➔ Controller ➔ Service ➔ DB処理 ➔ 画面の表示変化（トースト通知、リダイレクト、Props更新）までを**1本のシナリオ**として記録する。
  3. **未解析領域の更新**:
     まだ操作レベルまで解読できていない画面・ボタンがあれば `unexplored_domains` に残し、すべての画面・操作の追跡が完了するまで Phase 2/3 の深掘りを継続する。
  4. **コミット実行**:
     ```bash
     git add 02-knowledge/<リポジトリ名>/
     git commit -m "auto(doc): <リポジトリ名> の画面・操作挙動ナレッジ（ボタンレベル）を追加・更新"
     ```

- **必須記述フォーマット（02-knowledge 配下のノート構造）**:
  画面や操作説明を求められた際に即座に回答できるよう、以下の記述フォーマットを厳格に守ること。

  ```markdown
  ---
  created: YYYY-MM-DD
  updated: YYYY-MM-DD
  tags: [repository-name, screen-spec, user-action]
  phase: 2 # 全画面・ボタンの解読完了まで 3 にしない
  status: active
  unexplored_domains: ["管理画面のスタッフ承認ボタン挙動", "勤怠修正フォームの送信処理"]
  ---

  # [機能/画面名] 操作・挙動仕様ナレッジ

  ## 1. 画面概要・要素一覧 (Phase 1)
  - **対象画面**: ログイン画面 (`resources/js/Pages/Auth/Login.vue`)
  - **構成要素**: メールアドレス入力欄、パスワード入力欄、「ログイン」ボタン、「パスワードをお忘れの方」リンク

  ## 2. 操作トリガー別・詳細挙動トレース (Phase 2 必須)

  ### 操作A: 「ログイン」ボタン押下時
  - **画面上の動作**: 
    1. ボタンがローディング状態（非活性化）になる。
    2. 入力された `email`, `password`, `remember` を取得。
  - **裏での処理（コード連携）**:
    1. `Inertia.post('/login', form)` により POST リクエストを送信。
    2. Route: `routes/auth.php` ➔ `LoginController@store`
    3. `LoginRequest` でバリデーション（`email`: 必須/Email形式, `password`: 必須）。
    4. `Auth::attempt()` でパスワード照合およびセッション発行。
  - **処理結果と画面変化**:
    - **成功時**: マイページ (`/dashboard`) へリダイレクト。「ログインしました」のトースト表示。
    - **失敗時（パスワード誤り）**: 画面は遷移せず、「メールアドレスまたはパスワードが正しくありません」のエラーメッセージがパスワード欄下部に赤字表示される。

  ### 操作B: [○○機能] 「予約確定」ボタン押下時
  - **画面上の動作**: ...
  - **裏での処理**: ...
  - **他機能への影響（Phase 3 必須）**:

  ## 3. 例外・エラーハンドリング・表示制御 (Phase 3 必須)
  - **権限制御**: スタッフ権限がないユーザーの場合、このボタンは非活性（disabled）となり押下不可。
```

- **やらないこと**:
  - 「ログイン機能があります」「Controllerで処理します」といった、具体的なUI要素やデータ推移のわからない抽象的・大雑把な記述で終わらせること。
  - 画面上の「ボタン」や「入力フォーム」等のUI要素と、バックエンドコード（Controller/Service/DB）との具体的な対応関係を記述せずに放置すること。
  - 実際の Vue/Blade ファイルを参照（`read`/`view`）して `@click`, `v-model`, `submit` 等のコードを確認せずに、処理を推測で記述すること。
  - `04-resources/` 内の一次情報原本の改変・直接編集・削除。
  - 暗号鍵、APIキー、環境変数（.env）、絶対パス等の機密・セキュリティ情報の書き出し。

- **入力**:
  - `04-resources/git-repository/<リポジトリ名>/clone/<ブランチ>/` 配下のソースコード全域（特に `resources/js/Pages/`, `resources/views/`, `routes/`, `app/`）
  - `04-resources/git-repository/<リポジトリ名>/history/` 配下のログ・ファイルツリー

- **出力先**:
  - `02-knowledge/<リポジトリ名>/` 配下の Markdown ファイル群（`overview.md`, `screens.md`, `user-actions.md` 等）

- **終わりの条件**:
  - 全画面の全操作（ボタン押下・フォーム送信）に対する画面上の挙動・裏の処理フロー・データ変化が解読・記録されたこと。
  - ノート内の `unexplored_domains` が空（`[]`）になり、Frontmatter の `phase` が `3` へ引き上げられた状態で `git commit` が正常完了した時点。

- **止まる条件**:
  - `04-resources/git-repository/<リポジトリ名>/` 配下に対象コードが存在しない場合。
  - API のレートリミット（`Rate limit exceeded`）が発生した場合。
  - `pre-commit` フック等でエラーが発生し、自動修復が不可能な場合。

- **レートリミット・エラーハンドリング**:
  - API 制限（Quota / Rate limit）が発生した場合は、その時点で作成・更新が完了しているファイルのみを保存し、次回実行時に未解析の操作・画面（`unexplored_domains`）からスムーズにレジュームできるよう、進捗ログを出力して安全に終了すること。
