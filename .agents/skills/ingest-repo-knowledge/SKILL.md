# 役割

`04-resources/git-repository/<リポジトリ名>/` 内のソースコードを読み込み、`00-rules/workflow.md` で定義された **Knowledge Evolution（Phase 1〜3）** に従って `02-knowledge/<リポジトリ名>/` 配下のナレッジノートを全ドメイン網羅的に深掘り作成・更新し、Git コミットまで完結させる。

---

## 前提条件（共通ルールの確認）

- 作業開始時に、リポジトリルート直下の `AGENTS.md` および `00-rules/workflow.md` を必ず読み込み、そこに記載された「絶対遵守ルール」「ディレクトリ編集ポリシー」「ナレッジ育成ルール」に従うこと。

---

## 知識進化（Knowledge Evolution）進級判定規則

`02-knowledge/<リポジトリ名>/` 内のノートの Frontmatter (`phase`) を更新する際は、単に深く書けたかだけでなく**「リポジトリ全体の網羅率」**を基準として厳格に判定すること。

| Phase | 認定条件（すべて満たす必要がある） | 今回実行すべき深掘りタスク |
| :--- | :--- | :--- |
| **未作成** | ファイルが存在しない | **Phase 1 (概要・全構造把握)**: `routes/`, `app/` 配下の全サブフォルダをスキャンし、すべてのドメイン領域（例: 予約、勤怠、スタッフ、チャット等）を目録化 |
| **Phase 1** | 全体構造のみ記載されている | **Phase 2 (詳細・データフロー解読)**: 各ドメインの実装コードを直接閲覧し、具体的処理・データフローおよび**「ドメイン間の連携（例: 勤怠×予約シフト）」**を追記 |
| **Phase 2** | 全ドメインのコード処理と連携が解読完了 | **Phase 3 (背景・設計思想抽出)**: 抽出された全ドメインを俯瞰し、共通のアーキテクチャ方針、責務分離、状態管理、イベント駆動（Observer/Events）の設計思想を抽象化 |
| **Phase 3** | 全ドメインの解読および設計思想が完備 | **メンテナンス**: 直近の Git コミット差分を確認し、変更箇所のナレッジのみ追記・最新化 |

> ⚠️ **【重要】早期Phase 3化の禁止規則**  
> 一部のドメイン（例: 予約）のみ詳しく記述されていても、他に未解読のドメイン（例: 勤怠管理、報酬計算、管理画面機能など）が存在する場合は**絶対に Phase 3 を宣言してはならない（Phase 2にとどめて未解読領域を掘る）**。

---

## 仕事

- **実行手順**:
  1. **全容走査（ディレクトリ監査）**:
     `04-resources/git-repository/<リポジトリ名>/clone/<ブランチ>/` 配下の `app/Http/Controllers/`, `app/Services/`, `app/Models/`, `routes/` を確認し、リポジトリ内に存在する**すべてのドメイン領域（機能グループ）のリスト**を作成する。
  2. **既存ナレッジの網羅率チェック**:
     `02-knowledge/<リポジトリ名>/` 配下のノートを確認し、手順1で洗い出したドメイン領域のうち「まだノートに記載されていない機能」「触れられていないドメイン間連携（例: 勤怠管理と予約シフトの紐付け等）」を特定する。
  3. **コード読解と追記**:
     未解読ドメインのソースコード（Controller, Model, Service, FormRequest, Vue）を直接参照（`read`/`view`）し、データフローやドメイン相互作用をノートに書き込む。
  4. **Phase判定とFrontmatter更新**:
     未解読ドメインが残っている場合は `phase: 2` とし、`unexplored_domains` に残タスクを明記する。全ドメインの解読・連携が完了した場合のみ `phase: 3` に引き上げる。
  5. **コミット実行**:
     ```bash
     git add 02-knowledge/<リポジトリ名>/
     git commit -m "auto(doc): <リポジトリ名> のナレッジを更新（未解読ドメインの深掘り）"
     ```

- **必須記述フォーマット（02-knowledge 配下のノート構造）**:
  ```markdown
  ---
  created: YYYY-MM-DD
  updated: YYYY-MM-DD
  tags: [repository-name, laravel, vue, domain]
  phase: 2 # 全機能網羅まで 3 にしないこと
  status: active
  unexplored_domains: ["勤怠管理ドメイン", "報酬計算ロジック"] # 未解析の領域を明記
  ---

  # [リポジトリ/モジュール名] ナレッジノート

  ## 1. 識別された全ドメイン領域 (Phase 1)
  - [x] 予約管理ドメイン
  - [ ] 勤怠・シフト管理ドメイン（未完了）
  - [ ] チャットドメイン

  ## 2. ドメイン領域別詳細および相互連携 (Phase 2 必須)
  ### A. 予約管理ドメイン
  - **参照ファイル**: ...
  - **データフロー**: ...

  ### B. 勤怠・シフト管理ドメイン
  - **参照ファイル**: `app/Http/Controllers/Attendance/...`
  - **他ドメインとの連携・相互作用**:
    - 例: スタッフの勤怠打刻・シフトデータが、予約可能枠（`CalendarViewComponent`）の動的生成にどう影響するか等の連携コード解読結果

  ## 3. 全体アーキテクチャ・設計思想 (Phase 3 必須 - 全ドメイン解読後)
  - 全体を貫く設計原則、横断的関心事（ロギング、認可、イベント）

- **やらないこと**:
  - 一部の目立つ機能（例: 予約機能）だけを記述して「解読完了（Phase 3）」と判断すること。
  - `app/` や `routes/` 配下にある全ディレクトリ・ファイルの存在チェックを怠ること。
  - ソースコードの実際のファイルを閲覧（`read`/`view`）せずに、ディレクトリ構造やファイル名からの推測・目録の列挙のみで記述を終わらせること。
  - `04-resources/` 内の一次情報原本の改変・直接編集・削除。
  - 暗号鍵、APIキー、環境変数（.env）、絶対パス等の機密・セキュリティ情報の書き出し。

- **入力**:
  - `04-resources/git-repository/<リポジトリ名>/clone/<ブランチ>/` 配下のソースコード全域
  - `04-resources/git-repository/<リポジトリ名>/history/` 配下のログ・ファイルツリー

- **出力先**:
  - `02-knowledge/<リポジトリ名>/` 配下の Markdown ファイル群（`overview.md`, `architecture.md`, `domain-logic.md` 等）

- **終わりの条件**:
  - リポジトリ内の全ドメイン領域およびドメイン間連携の解読が完了し、`unexplored_domains` が空（`[]`）になったこと。
  - Frontmatter の `phase` が `3` へ更新され、コードレベルのデータフローおよび全体アーキテクチャ・設計思想が記録された状態で `git commit` が正常完了した時点。

- **止まる条件**:
  - `04-resources/git-repository/<リポジトリ名>/` 配下に対象コードが存在しない場合。
  - API のレートリミット（`Rate limit exceeded`）が発生した場合。
  - `pre-commit` フック等でエラーが発生し、自動修復が不可能な場合。

- **レートリミット・エラーハンドリング**:
  - API 制限（Quota / Rate limit）が発生した場合は、その時点で作成・更新が完了しているファイルのみを保存し、次回実行時に未解析ドメイン（`unexplored_domains`）から再開できるように進捗ログを出力して終了する。
