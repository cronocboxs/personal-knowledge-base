# 役割

`04-resources/git-repository/<リポジトリ名>/` 内のソースコード全域を技術スタック問わず自動スキャンし、**エントリーポイントから最深部の関数・プライベートロジック・DB・外部連携まで奥へ奥へ辿り**、既存ナレッジと比較した未確認領域の永久発掘ループを実施して `02-knowledge/<リポジトリ名>/` 配下に網羅蓄積する。

---

## 前提条件（共通ルールの確認）

- 作業開始時に、リポジトリルート直下の `AGENTS.md` および `00-rules/workflow.md` を必ず読み込むこと。

---

## 知識進化（ナレッジ育成）判定規則

| Phase | 判定基準 | 今回実行すべき解析・蓄積タスク |
| :--- | :--- | :--- |
| **Phase 1** | 未作成または `phase: 1` 指定 | **全機能・全インターフェースの目録化**: 全ファイルを走査し `overview.md` を作成。全領域を `unexplored_domains` に登録。 |
| **Phase 2** | `unexplored_domains` が存在する | **一巡処理・データ流転追跡**: 各トリガーに対する入力・バックエンド処理・DB・レスポンスをトレースし本文記述。 |
| **Phase 3** | 一巡処理完了 (`unexplored_domains` が空) | **仕様網羅・ドメイン間連動**: 例外ハンドリング、権限、副作用、設計意図の解読。 |
| **Phase 4** | 最深部ロジック解読中 | **最深部追跡（Deep Logic Trace）**: 表面層を超え、呼び出されているプライベート関数・内部ライブラリ・DBトランザクション・非同期処理まで奥へ辿る。 |
| **Phase 5** | 全走査・ナレッジ比較検証中 | **継続的再走査と差分発掘**: コード全域を再走査し、ナレッジ未記載の「奥のロジック」を発掘。発見時は `unexplored_domains` に追記して Phase 2/4 へ戻す。 |

---

## 仕事

- **実行手順**:
  0. **グラフ解析データ（インデックス）の事前ロード**:
     - ファイル探索に入る前に、`04-resources/git-repository/<リポジトリ名>/graph/<ブランチ>/` 内の生成物をロードする。
       - `code-graph.json` または `code-graph-report.md`: クラス・関数・依存関係ツリーの全体像を把握。
       - `doc-graph.json` または `doc-graph-report.md`: ドキュメント間の相関を把握。
     - **効果**: 全ファイルを個別に開いて探す無駄を省き、グラフ上の呼び出し関係（エッジ）を元に目的の処理・深層関数が配置されているファイルを直接狙い撃ちして閲覧（`read`/`view`）する。
  1. **全件コード走査 & ナレッジ比較（継続的発掘）**:
     - 対象リポジトリの全コードおよび `code-graph.json` を走査し、既存の `02-knowledge/` に蓄積されている内容と比較する。
     - **「まだ本文に詳しく書かれていないプライベート関数、コールバック、DBクエリ生成、エラー分岐、ライブラリ内部処理」**を発掘し、すべて Frontmatter の `unexplored_domains` に追加する。
  2. **最深部までのトリガー別処理追跡（Phase 2 & Phase 4）**:
     - `unexplored_domains` から対象を選択し、`code-graph.json` の依存関係を辿りながら該当ソースコードを直接閲覧（`read`/`view`）する。
     - 単なる「APIを呼んでDBに保存する」といった表面的な追跡で終わらせず、**「その内部で呼ばれている関数 A ➔ 関数の内部で実行されるプライベート処理 B ➔ 発火するイベント C ➔ 処理されるクエリ D」**のように奥へ奥へ遡って追跡し、本文に記述する。
     - 追跡・記述が完了したドメインのみ `unexplored_domains` から除外する。
  3. **自動ループレジューム判定とコミット**:
     - `unexplored_domains` が消化されて空（`[]`）になった場合でも、完了とせず **Phase 5（再走査・比較）** を実行する。
     - 再走査で新たな深層領域が見つかった場合は `phase: 2` または `phase: 4` に設定して `unexplored_domains` に登録し、処理を無限に深掘り展開する。
     - 新たな領域が一切見つからない完全網羅状態の時のみ `phase: 5` を付与してコミットする。
     ```bash
     git add 02-knowledge/<リポジトリ名>/
     git commit -m "auto(doc): <リポジトリ名> の最深部処理ナレッジを更新・差分発掘 (Phase: X)"
     ```
  4. 「datasource.md と overview.md の unexplored_domains に書いてある "認証・認可基盤 app/Http/Middleware/CheckPermission.php の最深部権限チェックロジック" を今すぐ解析してください。
解析結果を datasource.md の本文に追記し、実際にファイルを書き換えた上で unexplored_domains からその項目を削除して保存してください。完了サマリーの出力だけで終わらせないでください。」

- **必須記述フォーマット（02-knowledge 配下のノート構造）**:

  ```markdown
  ---
  created: YYYY-MM-DD
  updated: YYYY-MM-DD
  tags: [repository-name, spec, code-analysis]
  phase: 2
  status: active
  unexplored_domains:
    - "モジュールAの内部関数 `PrivateHelper::processInternal()` (`path/to/file`)"
    - "モデルBのイベントフック `beforeSave()` 内の非同期キュー発行ロジック"
  ---

  # [モジュール/ドメイン名] 挙動・最深部仕様ナレッジ

  ## 1. 識別された機能・インターフェース一覧 (Phase 1)
  - [x] 機能/エンドポイントA (`path/to/source_a`)

  ## 2. インターフェース・最深部処理トレース (Phase 2 & Phase 4 必須)

  ### 機能1: [対象機能/画面/API/コマンド名]
  #### トリガー1: 「[操作・呼び出しトリガー]」
  - **最深部までの処理流転（Deep Logic Execution Flow）**:
    1. **エントリーポイント**: パラメーター受取とバリデーション。
    2. **サービス・ドメイン層**: メインビジネスロジック。
    3. **内部プライベート関数・ヘルパー**: (例: `Helper::calculate()` への進入と内部条件分岐)。
    4. **データ永続化・低層処理**: (例: トランザクション処理、実行される生クエリ/ORM挙動)。
    5. **副作用・非同期イベント**: (例: キューへのJob投入、外部Webhook呼び出し)。
  - **出力・応答・状態変化**:
    - **成功/失敗時の最深部挙動**: ロールバック条件、例外キャッチ時のリカバリ処理。

  ## 3. 再走査・深層比較ログ (Phase 5)
  - **最終再走査日**: YYYY-MM-DD
  - **発掘された未確認領域・補全履歴**:
    - YYYY-MM-DD: `Helper::calculate()` 内のエッジケース分岐を発掘・追記。
  ```

- **やらないこと**:
  - コントローラーや公開APIの表面的な呼出関係だけで「解析完了」と判断してストップすること。
  - レジューム・APIリミット復帰時に、単に前回の続きだけを流し読みして全域再走査・差分比較を怠ること。
  - 内部関数やデータ構造の奥深くまで辿らずに `phase: 3` や `phase: 5` を宣言すること。
  - 本文の加筆を行わずに Frontmatter の未解析リストだけを消去すること。

- **絶対にやってはならない不正判定（アンチパターン）**:
  - 本文に深い処理トレースを加筆せず、Frontmatter の `unexplored_domains` を空（`[]`）にして手抜きで Phase 昇進させること。

- **入力**:
  - `04-resources/git-repository/<リポジトリ名>/clone/<ブランチ>/` 配下のソースコード全域
  - `04-resources/git-repository/<リポジトリ名>/graph/<ブランチ>/code-graph.json` (解析インデックス)

- **出力先**:
  - `02-knowledge/<リポジトリ名>/` 配下の Markdown ファイル群

- **終わりの条件**:
  - **1回のセッションで処理する unexplored_domains は原則「10件」** とする。処理・ファイル更新・コミット完了後はセッションを終了すること。
  - リポジトリ内のすべての機能・最深部ロジック（関数・低層処理・例外）が解読され、再走査を行っても新規未確認領域が0件となった時点。

- **止まる条件**:
  - `04-resources/git-repository/<リポジトリ名>/` 配下に対象コードが存在しない場合。
  - `pre-commit` フック等で修復不可能なエラーが発生した場合。
