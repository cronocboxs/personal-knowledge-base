# 役割

`04-resources/git-repository/<リポジトリ名>/` 内のソースコード全域を自動スキャンし、**エントリーポイントから最深部の関数・プライベートロジック・DB・外部連携まで奥へ奥へ辿り**、既存ナレッジと比較した未確認領域の発掘と記述を行い `02-knowledge/<リポジトリ名>/` 配下に網羅蓄積する。

---

## 前提条件（共通ルールの確認）

- 作業開始時に、リポジトリルート直下の `AGENTS.md` および `00-rules/workflow.md` を必ず読み込むこと。

---

## 知識進化（ナレッジ育成）判定規則

| Phase | 判定基準 | 今回実行すべき解析・蓄積タスク |
| :--- | :--- | :--- |
| **Phase 1** | 未作成または `phase: 1` 指定 | **全機能・全インターフェースの目録化**: 全ファイルを走査し `overview.md` を作成。全領域を `unexplored_domains` に登録。 |
| **Phase 2** | `unexplored_domains` が存在する | **一巡処理・データ流転追跡**: 各トリガーに対する入力・バックエンド処理・DB・レスポンスをトレースし本文記述。 |
| **Phase 3** | 一巡処理完了 (`unexplored_domains` が空) | **仕様網羅・ドメイン間連動**: 例外ハンドリング、権限、副作用、設計意図の解読。 |
| **Phase 4** | 最深部ロジック解読中 | **最深部追跡（Deep Logic Trace）**: 表面層を超え、呼び出されているプライベート関数・内部ライブラリ・DBトランザクション・非同期処理まで奥へ辿る。 |
| **Phase 5** | 全走査完了・完全網羅状態 | **定期再走査**: リポジトリ全体の新規変更や未記載ロジックの有無を確認。 |

---

## 仕事

- **APIレートリミット回避ルール（15 RPM対策）**:
  - ツール呼び出し（ファイル読み取りや検索）を **6〜8回** 実行するごとに、必ずシェルコマンド `sleep 20` を実行して自律的に 20 秒間待機すること。

- **実行手順**:
  0. **グラフ解析データ（インデックス）の事前ロード**:
     - `04-resources/git-repository/<リポジトリ名>/graph/<ブランチ>/` 内の `code-graph.json` や `code-graph-report.md` を確認し、呼び出しツリーの全体像を把握する。
  1. **未解析領域（`unexplored_domains`）の順次消化**:
     - ナレッジノート Frontmatter の `unexplored_domains` から未解析項目を取得する。
     - 該当するソースコードを閲覧（`read`/`view`）し、表面層だけでなく呼び出されているプライベート関数・SQL・非同期処理等の最深部まで追跡する。
  2. **ナレッジ本文の更新とリストからの削除**:
     - 解読したロジックをノート本文の `## 2. インターフェース・最深部処理トレース` に追加記述する。
     - **記述が完了した項目のみ** `unexplored_domains` から確実に削除（除外）して保存する。
  3. **新規領域の追加制約（乱発防止）**:
     - 解析途中で新たな未解析領域を発見した場合のみ `unexplored_domains` に追加してよい。
     - ただし、「〜の理解」「Viteの構成」といった抽象的な課題ではなく、**具体的に未解析のファイルパスや関数名（例: `Class::method()`）が特定できた場合のみ** 追記すること。
  4. **コミットと同期**:
     - 1回の作業が終わったら、以下のコマンドでインデックスの同期と git commit を実行する。
     ```bash
     ./scripts/run-markdown-index.sh 02-knowledge/<リポジトリ名>
     git add 02-knowledge/<リポジトリ名>/
     git commit -m "auto(doc): <リポジトリ名> の最深部処理ナレッジを更新"
     ```

- **終わりの条件**:
  - ノート Frontmatter の `unexplored_domains` がすべて消化されて空（`[]`）になった時点（Phase 3 または Phase 5 へ遷移して終了）。
  - または、1回のセッションで `unexplored_domains` を着実に減らし、本文の追記とコミットを正しく完了した時点。

- **やらないこと**:
  - 本文への具体的な加筆を行わずに `unexplored_domains` の項目だけを消去すること。
  - 「〜の理解」などの抽象的な言葉で `unexplored_domains` を無限に再登録し続けること。

- **ログ出力ルール**:
  - 各ナレッジノート本文には実行ログを記述しないこと。
  - 走査・更新履歴は `04-resources/logs/analysis-history/<リポジトリ名>.log` に日時・対応内容・発掘領域を追記すること。
